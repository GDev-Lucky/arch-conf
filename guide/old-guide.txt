MINIMAL ARCH -> LEAN HYPRLAND FIELD GUIDE
=============================================
Verified against Arch/Hyprland state on 2026-10-02.

GOAL
----
Build Arch from the smallest practical supported base, understand each major
tool you intentionally add, automate each stage with simple Bash scripts, and
end with a fast daily-drivable Hyprland system.

Final desktop idea:

    TTY login
        -> start-hyprland
        -> Hyprland
           |- foot                 terminal
           |- fuzzel               app launcher
           |- mako                 notifications
           |- wl-clipboard         clipboard primitives
           |- cliphist             OPTIONAL clipboard history
           |- grim + slurp         screenshots / region selection
           |- PipeWire             media graph / audio server
           |- WirePlumber          PipeWire policy/session manager
           |- xdg-desktop-portal
           |- xdg-desktop-portal-hyprland
           |- terminal FileChooser portal using fd + fzf
           |- Waybar               OPTIONAL status bar
           |- Neovim               first/only text editor in this guide

Deliberately NOT installed by this guide:
    - desktop environment
    - graphical login/display manager
    - graphical file manager
    - Nano/Vim/Emacs before Neovim
    - NetworkManager
    - dhcpcd
    - PulseAudio daemon
    - graphical package manager
    - AUR helper such as yay/paru
    - man-db / man-pages / texinfo
    - separate documentation packages
    - wallpaper program unless you later decide you want one

IMPORTANT IDEA
--------------
"Minimal" does NOT mean literally two packages.

Arch's supported minimum is the `base` metapackage. It pulls fundamental
userspace such as:

    systemd
    pacman
    bash
    coreutils
    glibc
    grep
    sed
    findutils
    util-linux
    iproute2
    iputils
    procps-ng
    shadow
    tar/gzip/xz
    ...

Those are the floor. Do not try to individually remove random base
dependencies.

Your learning rule is:

    LOW-LEVEL LIBRARY DEPENDENCY
        Let pacman resolve it.

    MAJOR TOOL / DAEMON / COMMAND / SUBSYSTEM
        Add it deliberately.
        Know why it exists.
        Prefer giving it its own install script/stage.

Examples worth deliberately learning:
    git, ssh, systemd-networkd, iwd, pactree, strace, lsof, fd, fzf, rg,
    jq, gcc, make, binutils, Neovim, Wayland, PipeWire, WirePlumber,
    Hyprland, XDG portals, grim, slurp, wl-copy/wl-paste.

== 02. FIRST BASH SKILL: WRITE SCRIPTS WITHOUT AN EDITOR ==
===============================================================================

You do NOT need Nano just to create files.

Create a file with a heredoc:

    cat > hello.sh <<'EOF'
    #!/usr/bin/env bash
    set -euo pipefail

    echo "hello"
    EOF

Make it executable:

    chmod +x hello.sh

Run it:

    ./hello.sh

Inspect it:

    cat hello.sh

Append one line:

    printf '%s\n' 'echo "another line"' >> hello.sh

Replace text:

    sed -i 's/another line/replaced line/' hello.sh

== 06. PARTITIONING ==
===============================================================================

DANGER:
    This is the destructive part.
    NEVER blindly paste device names from an example.

Inspect:

    lsblk -f
    fdisk -l

A simple fresh-disk layout:

    GPT
    |- 1 GiB EFI System Partition   FAT32   -> /boot
    `- remaining root partition     ext4    -> /

If dual booting:
    - DO NOT format an existing Windows ESP.
    - Reuse it only if you intentionally want to and it has enough space.
    - A separate ~1 GiB Arch ESP is often simpler for experimentation.
    - Windows can remain independently bootable through UEFI firmware.

Open partition editor:

    fdisk /dev/nvme0n1

Useful fdisk keys:

    p       print table
    g       create GPT (DESTROYS existing partition table)
    n       new partition
    t       change partition type
    d       delete partition
    w       write changes
    q       quit without writing

Re-check after partitioning:

    lsblk -f

EXAMPLE names only:

    ESP=/dev/nvme0n1p1
    ROOT=/dev/nvme0n1p2

Format ONLY newly-created partitions:

    mkfs.fat -F 32 "$ESP"
    mkfs.ext4 "$ROOT"

Mount:

    mount "$ROOT" /mnt
    mount --mkdir "$ESP" /mnt/boot

Verify:

    findmnt /mnt
    findmnt /mnt/boot

== 07. REMOVE NORMAL DOCUMENTATION FROM PACKAGE EXTRACTION ==
===============================================================================

You said you do not want local manuals/docs.

Do NOT install:

    man-db
    man-pages
    texinfo

Many ordinary packages still contain files under /usr/share/man or
/usr/share/doc. Pacman supports `NoExtract`, so prevent common documentation
trees from being written in the first place.

Create a temporary minimal pacman config in the ISO:

    cp /etc/pacman.conf /root/pacman-min.conf

Insert the rule immediately after [options]:

    sed -i '/^\[options\]/a NoExtract = usr/share/man/* usr/share/doc/* usr/share/info/* usr/share/gtk-doc/* usr/share/help/*' /root/pacman-min.conf

Verify:

    grep -n 'NoExtract' /root/pacman-min.conf

This intentionally DOES NOT remove:
    /usr/share/licenses

Licenses are tiny and package/legal metadata.

Do not start inventing broad wildcards such as deleting all /usr/share.
Applications keep real runtime data there.

    FAT utilities/checker for the EFI partition.

== 13. BOOT: SYSTEMD-BOOT ==
===============================================================================

No GRUB package required.

systemd already contains:

    bootctl
    systemd-boot EFI binary

Install:

    bootctl install

Create loader config:

    mkdir -p /boot/loader/entries

    cat > /boot/loader/loader.conf <<'EOF'
    default arch.conf
    timeout 2
    editor no
    EOF

Get ROOT filesystem UUID:

    blkid

Create entry, replacing ROOT_UUID:

    cat > /boot/loader/entries/arch.conf <<'EOF'
    title   Arch Linux
    linux   /vmlinuz-linux
    initrd  /initramfs-linux.img
    options root=UUID=ROOT_UUID rw
    EOF

Then replace:

    sed -i 's/ROOT_UUID/YOUR-ACTUAL-UUID/' /boot/loader/entries/arch.conf

Modern mkinitcpio can pack CPU microcode into the main initramfs through its
`microcode` hook.

Check hooks:

    grep '^HOOKS=' /etc/mkinitcpio.conf

Make sure `microcode` exists in HOOKS. If needed, change the line with sed.

Regenerate:

    mkinitcpio -P

Confirm boot files:

    ls -lh /boot

Inspect boot config:

    bootctl list

== 17. PACKAGE TRANSPARENCY HABIT ==
===============================================================================

Before installing an important package:

1. Read package metadata:

    pacman -Si PACKAGE

2. Preview the transaction WITHOUT installing:

    pacman -Sp --needed --print-format '%n  %v  %s  %d' PACKAGE

3. Search package database:

    pacman -Ss SEARCH

4. After installation, list files:

    pacman -Ql PACKAGE

5. Find which installed package owns a file:

    pacman -Qo /usr/bin/COMMAND

6. Explicit packages:

    pacman -Qe

7. Dependency packages:

    pacman -Qd

8. Orphans:

    pacman -Qdt

Do NOT use:

    pacman -Sdd
    pacman --nodeps

Dependencies exist for a reason.

Your goal is visibility, not breaking dependency resolution.

== 21. BASH + FILESYSTEM CHEAT SHEET ==
===============================================================================

PATHS
-----

    /               filesystem root
    ~               current user's home
    .               current directory
    ..              parent directory
    -               previous directory (with cd)
    ./file           file relative to current directory
    /path/file       absolute path

Important Linux paths:

    /boot            bootloader/kernel/initramfs in this setup
    /dev             device nodes
    /etc             system configuration
    /home            user homes
    /proc            process/kernel virtual filesystem
    /root            root user's home
    /run             runtime state
    /sys             kernel/device virtual filesystem
    /tmp             temporary files
    /usr/bin         most commands
    /usr/lib         libraries + system components
    /usr/share       architecture-independent package data
    /var             logs/cache/mutable service data
    ~/.config        per-user application config
    ~/.local         per-user data/programs
    ~/.cache         disposable per-user cache
    ~/src            this guide's source/project directory


NAVIGATION
----------

    pwd                         where am I
    ls                          list
    ls -la                      include hidden + details
    ls -lh                      human sizes
    cd PATH                     change directory
    cd                          home
    cd ..                       parent
    cd -                        previous directory
    find PATH -name PATTERN     recursive file search


FILES
-----

    touch FILE                  create/update timestamp
    mkdir DIR                   create directory
    mkdir -p A/B/C              create parent chain
    cp A B                      copy
    cp -r A B                   recursive copy
    mv A B                      move/rename
    rm FILE                     delete file
    rm -r DIR                   recursive delete
    ln -s TARGET LINK           symlink
    readlink LINK               see symlink target
    file PATH                   identify file type
    stat PATH                   detailed metadata


READ / SEARCH
-------------

    cat FILE
    head -n 50 FILE
    tail -n 50 FILE
    tail -f FILE                follow growing log
    grep PATTERN FILE
    grep -n PATTERN FILE        line numbers
    grep -r PATTERN DIR         recursive
    sed -n '20,80p' FILE        print line range
    wc -l FILE                  line count


REDIRECTION / PIPES
-------------------

    CMD > file                  stdout -> replace file
    CMD >> file                 stdout -> append file
    CMD 2> file                 stderr -> file
    CMD > file 2>&1             stdout + stderr -> file
    A | B                       A's stdout becomes B's stdin
    CMD < file                  file becomes stdin

Examples:

    ps aux | grep pipewire
    journalctl -b | grep -i error
    printf '%s\n' hello > file.txt


BASH VARIABLES
--------------

    name="value"
    echo "$name"

Environment variable:

    export NAME="value"

Command substitution:

    kernel="$(uname -r)"
    echo "$kernel"

Default value:

    value="${VALUE:-default}"

Arguments:

    $0      script name
    $1      first argument
    $2      second
    "$@"    all arguments safely


CONDITIONS
----------

    if [[ -f "$file" ]]; then
        echo exists
    fi

Common tests:

    -f FILE     regular file
    -d DIR      directory

== 26. GPU / GRAPHICS FOUNDATION BEFORE HYPRLAND ==
===============================================================================

Hyprland is not the GPU driver.

Conceptual stack:

    hardware
      -> kernel DRM/KMS driver
      -> firmware (when required)
      -> userspace graphics driver
      -> EGL/OpenGL/Vulkan
      -> Wayland compositor (Hyprland)

Inspect:

    lspci -k | grep -A3 -E 'VGA|3D|Display'

AMD common userspace:

    mesa
    vulkan-radeon          OPTIONAL if you need Vulkan

Intel common userspace:

    mesa
    vulkan-intel           OPTIONAL if you need Vulkan

NVIDIA:
    Treat separately.
    NVIDIA/Hyprland compatibility details change frequently.
    Check the CURRENT Hyprland NVIDIA page before installing driver packages.
    Do not blindly copy old NVIDIA environment-variable guides.

For AMD/Intel, install `mesa` explicitly before Hyprland so you understand that
it is your userspace graphics implementation rather than allowing it to feel
like a mysterious compositor dependency.

Example:

    pacman -Sp --needed --print-format '%n  %v  %s  %d' mesa
    pacman -S --needed mesa

Learn:

    /dev/dri/*
        DRM devices exposed by kernel.

    ls -l /dev/dri

== 27. WAYLAND CONCEPT BEFORE HYPRLAND ==
===============================================================================

Understand these roles:

    Linux kernel
        hardware, DRM/KMS, input devices

    libinput
        normalized keyboard/mouse/touchpad input library

    Wayland

    compositor

    bind = $mod, J, movefocus, d
    bind = $mod, K, movefocus, u

    bind = $mod SHIFT, J, movewindow, d
    bind = $mod SHIFT, K, movewindow, u
    bind = $mod SHIFT, L, movewindow, r

    bind = $mod, 1, workspace, 1
    bind = $mod, 2, workspace, 2
    bind = $mod, 3, workspace, 3
    bind = $mod, 4, workspace, 4
    bind = $mod, 5, workspace, 5
    bind = $mod, 6, workspace, 6
    bind = $mod, 7, workspace, 7
    bind = $mod, 8, workspace, 8
    bind = $mod, 9, workspace, 9

    bind = $mod SHIFT, 1, movetoworkspace, 1
    bind = $mod SHIFT, 2, movetoworkspace, 2
    bind = $mod SHIFT, 3, movetoworkspace, 3
    bind = $mod SHIFT, 4, movetoworkspace, 4
    bind = $mod SHIFT, 5, movetoworkspace, 5
    bind = $mod SHIFT, 6, movetoworkspace, 6
    bind = $mod SHIFT, 7, movetoworkspace, 7
    bind = $mod SHIFT, 8, movetoworkspace, 8
    bind = $mod SHIFT, 9, movetoworkspace, 9

    general {
        gaps_in = 2

== 38. TERMINAL FILE CHOOSER: NO GRAPHICAL FILE MANAGER ==
===============================================================================

Goal:

    browser/Discord/app requests "choose file"
      -> XDG FileChooser portal
      -> small foot window
      -> fd generates files
      -> fzf selects one
      -> selected path returned to application

No Nautilus.
No Dolphin.
No Thunar.
No PCManFM.

Current Arch status:
    xdg-desktop-portal-termfilechooser is an AUR package rather than an
    official repository package.

For your learning goals:
    DO NOT install an AUR helper just for this.

Instead, once you reached the base-devel stage:

    git clone https://aur.archlinux.org/xdg-desktop-portal-termfilechooser-hunkyburrito-git.git
    cd xdg-desktop-portal-termfilechooser-hunkyburrito-git

READ BEFORE BUILDING:

    cat PKGBUILD
    grep -nE '^(pkgname|pkgver|depends|makedepends|source)=' PKGBUILD

Build/install as NORMAL USER:

    makepkg -si

Never run makepkg as root.

Find installed example fzf wrapper:

    pacman -Ql xdg-desktop-portal-termfilechooser-hunkyburrito-git | grep fzf

Create config:

    mkdir -p ~/.config/xdg-desktop-portal-termfilechooser

Use the installed fzf wrapper path shown by pacman -Ql.

Typical idea:

    ~/.config/xdg-desktop-portal-termfilechooser/config

    [filechooser]
    cmd=fzf-wrapper.sh
    default_dir=$HOME
    env=TERMCMD=foot -T "file chooser"
    open_mode=suggested
    save_mode=last

Route only FileChooser to termfilechooser:

    mkdir -p ~/.config/xdg-desktop-portal

    cat > ~/.config/xdg-desktop-portal/portals.conf <<'EOF'
    [preferred]
    default=hyprland
    org.freedesktop.impl.portal.FileChooser=termfilechooser
    EOF

Restart portals:

    systemctl --user restart xdg-desktop-portal.service

Debug:

    systemctl --user status xdg-desktop-portal.service
    journalctl --user -eu xdg-desktop-portal-termfilechooser

IMPORTANT:
    Not every non-sandboxed app always chooses to use the XDG file portal.
    Some apps/toolkits may need an environment setting or app-specific option.

For GTK apps that support portal forcing, a common knob is:

    GTK_USE_PORTAL=1

Do not globally force it until you test your actual apps.

== 45. SIMPLE INSTALL-SCRIPT STYLE ==
===============================================================================

A shared helper can stay tiny.

Create:

    cat > ~/src/launch/lib/common.sh <<'EOF'
    #!/usr/bin/env bash

    require_root() {
        if (( EUID != 0 )); then
            echo "this script must run as root"
            exit 1
        fi
    }

    preview() {
        pacman -Sp --needed --print-format '%n  %v  %s  %d' "$@"
    }

    install_packages() {
        pacman -S --needed "$@"
    }
    EOF

Example stage:

    cat > ~/src/launch/install/70-desktop-tools.sh <<'EOF'
    #!/usr/bin/env bash
    set -euo pipefail

    ROOT="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")/.." && pwd)"
    source "$ROOT/lib/common.sh"

    require_root

    packages=(
        foot
        fuzzel
        mako
        wl-clipboard
        grim
        slurp
    )

    preview "${packages[@]}"
    install_packages "${packages[@]}"
    EOF

Keep configuration deployment separate:

    install package
    then link/copy config

This makes rerunning safe:

    pacman -S --needed ...

== 46. OPTIONAL TOGGLES WITHOUT BUILDING A CONFIG LANGUAGE ==
===============================================================================

Use environment variables or Bash variables.

Example:

    WITH_WAYBAR="${WITH_WAYBAR:-0}"
    WITH_CLIPHIST="${WITH_CLIPHIST:-1}"

    if [[ "$WITH_WAYBAR" == 1 ]]; then
        packages+=(waybar)
    fi

Run:

    WITH_WAYBAR=1 ./install/desktop.sh

Or config file:

    ~/src/launch/machine.conf

    WITH_WAYBAR=1
    WITH_CLIPHIST=1
    BROWSER=firefox

Script:

    source "$ROOT/machine.conf"

Do NOT write a custom parser until Bash stops being enough.

== 50. PACKAGE CACHE CLEANUP ==
===============================================================================

Pacman intentionally caches downloaded package archives.

See size:

    du -sh /var/cache/pacman/pkg

With pacman-contrib:

    paccache -d

Clean older versions while retaining recent rollback candidates:

    paccache -r

Do NOT obsessively delete every cached previous version.
A small rollback window is useful on rolling release systems.

== 51. CHECK WHAT YOU INTENTIONALLY INSTALLED ==
===============================================================================

This is one of your most important commands:

    pacman -Qe

Your ideal reaction to every line:

    "I know what that is and why I explicitly installed it."

Dependencies:

    pacman -Qd

You do NOT need to memorize every shared library.

For a mystery dependency:

    pacman -Qi PACKAGE
    pactree -r PACKAGE

For mystery file:

    pacman -Qo PATH

For mystery command:

    command -v COMMAND
    pacman -Qo "$(command -v COMMAND)"

== 52. NO MANUALS / DOCS POLICY ==
===============================================================================

Do not install:

    man-db
    man-pages
    texinfo
    *-docs packages unless actually required

Pacman NoExtract policy established during bootstrap:

    usr/share/man/*
    usr/share/doc/*
    usr/share/info/*
    usr/share/gtk-doc/*
    usr/share/help/*

Check effective config:

    pacman-conf NoExtract

Some applications intentionally ship documentation-like data inside their own
runtime trees.

Do NOT aggressively delete arbitrary package-owned runtime directories just
because their name contains "doc".

Your phone/browser is your external documentation.

===============================================================================
== 53. THINGS NOT TO OPTIMIZE TOO EARLY ==
===============================================================================

Do not immediately:

    - custom-compile your kernel
    - disable random systemd units you do not understand
    - remove base packages
    - use --nodeps
    - replace glibc
    - hand-delete package-owned libraries
    - build Hyprland from git
    - use giant dotfile frameworks
    - write your own package manager
    - use an AUR helper before learning PKGBUILDs/makepkg
    - enable every compositor effect and then benchmark "Linux performance"

First make the system:
    understandable
    reproducible
    observable
    bootable

Then optimize measured problems.

== 54. WHAT "PERFORMANT" SHOULD MEAN HERE ==
===============================================================================

Good targets:

    little idle CPU use
    few unnecessary daemons
    low input latency
    no desktop shell you do not use
    simple compositor config
    no blur/shadow if you do not care about them
    fast terminal/launcher
    correct GPU drivers
    no needless autostarts
    no huge app stacks merely for tiny functionality

Do NOT measure success solely by:
    package count
    20 MB of disk difference
    shaving a few MB RAM from an idle bar

A correct graphics/audio stack is more important than artificial package-count
minimalism.

== 56. THE LEARNING LOOP ==
===============================================================================

Every time you want a new capability:

1. Define the capability.

    "I need screenshots."

2. Find the smallest tool that does it.

    grim + slurp

3. Search:

    pacman -Ss grim
    pacman -Si grim

4. Preview transaction:

    pacman -Sp --needed --print-format '%n  %v  %s  %d' grim slurp

5. If interesting:

    pactree grim

6. Write the install script BEFORE installing it.

7. Commit:

    git add .
    git commit -m "add screenshot tooling"

8. Run script as root.

9. Learn the commands the package added.

10. Add config/keybind.

11. Commit again.

12. Inspect processes/services if it created any.

13. Push:

    git push

That loop is the entire philosophy of this machine.

== 58. CURRENT-STATE NOTES (2026-10-02) ==
===============================================================================

These details are intentionally dated because rolling-release systems change.

At the time this guide was written:

    Arch `base`
        is the supported minimal package set and includes systemd, pacman,
        Bash, coreutils, grep, sed, findutils, iproute2, procps-ng, util-linux,
        and related foundations.

    Arch `linux`
        requires an initramfs provider. This guide explicitly chooses
        mkinitcpio.

    systemd
        already ships systemd-boot/bootctl, networkd, resolved, timesyncd and
        many useful inspection commands.

    Hyprland
        is in Arch's official repositories.
        Start from TTY with:
            start-hyprland

    foot
        is an official Arch package and is a lightweight Wayland terminal.

    fuzzel
        is available in official Arch repositories.

    mako
        is available in official Arch repositories.

    wl-clipboard
        provides wl-copy / wl-paste.

    grim + slurp
        are the minimal Wayland screenshot/selection pair used here.

    xdg-desktop-portal-hyprland
        is an official Arch package.

    xdg-desktop-portal-termfilechooser
        is currently an AUR-style package rather than an official repository
        package, so this guide intentionally teaches `makepkg` instead of
        installing an AUR helper.

    Waybar
        is polished but has a considerably larger dependency closure than the
        extremely minimal components above, so it stays optional/late.

When this file becomes old:

    pacman -Ss PACKAGE
    pacman -Si PACKAGE
    pacman -Sp --needed PACKAGE

and current Arch/Hyprland upstream information should win over this TXT.
